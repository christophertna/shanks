Shanks feature roadmap

Priority 1 - Safety-critical

1- [DONE] Scope the build agent's tools, not just the critic/debugger's.
    Every read-only path (DebuggerAdapter, ClaudeAdapter(read_only=True),
    both critic adapters) runs Claude with `--permission-mode plan --tools
    Read` or Codex with `--sandbox read-only`. The build path doesn't:
    RalphAdapter's scripts/ralph/ralph.sh runs Claude with
    `--dangerously-skip-permissions` (blanket bypass, no tool allowlist) and
    Codex with `--sandbox workspace-write` (directory-scoped but otherwise
    unrestricted); ClaudeAdapter(read_only=False) does the same
    skip-permissions thing. SubprocessAgentAdapter._validate_execution only
    gates which executable/paths can *launch* the agent - it says nothing
    about what the agent does once it's running, so it isn't a substitute.
    Fix: drop `--dangerously-skip-permissions` on the Claude build path and
    reuse the pattern that's already in this same file - explicit
    `--permission-mode acceptEdits --tools Read,Write,Edit,Bash` (or
    whatever the build step actually needs), same shape as the existing
    `--tools Read` calls, just with write/exec added. That gets it off the
    all-or-nothing bypass without inventing a new mechanism. Codex's
    workspace-write is already reasonably scoped; leave it.

2- The dangerous-command hook guard doesn't reach Ralph's builder at all.
    hooks/deny-dangerous.sh is wired through .claude/settings.json's
    PreToolUse Bash matcher and is independent of permission mode - it
    should be the one backstop that survives --dangerously-skip-permissions.
    But .claude/ is gitignored (.gitignore:12), and RunWorkspaceManager.ensure()
    (workflow/workspaces.py:98) creates each run's isolated workspace with
    plain `git worktree add`, which only checks out tracked files.
    scripts/ralph/ralph.sh then `cd`s into that worktree before invoking
    `claude`, so the CLI finds no .claude/settings.json there and
    deny-dangerous.sh never fires for an actual graph-driven build - only
    for interactive sessions run from the main checkout. Fix: copy (or
    symlink) .claude/settings.json and hooks/ into each new worktree as
    part of RunWorkspaceManager.ensure(), right after `git worktree add`
    succeeds - same lazy shape as the rest of that method, no new
    mechanism needed.

Priority 2 - Maintenance and developer experience

1- GitHub token permission documentation.
    Document the exact token permissions the GitHub handoff needs (at least
    Contents and Pull requests, read and write, for a fine-grained PAT) so
    setup failures surface as a doc reference instead of a live 403 diagnosis.

2- Scoped test-impact hook.
    Add a `PostToolUse` hook on `Write|Edit` that runs just the test module
    matching the touched file (e.g. `workflow/workspaces.py` ->
    `tests.test_workspaces`) so regressions surface on every edit without
    paying for a full suite run each time.

Suggestions

- Real-agent smoke tests (tests/test_agent_integration.py) only cover the
  Codex and Claude planner/builder adapters; the GPT-5.6 Luna and Claude
  Opus 4.8 critic adapters still have no real-CLI coverage. Extend once
  there's an authenticated environment to run them in.
- Wire tests/test_agent_integration.py into an opt-in, manually-triggered CI
  job (workflow_dispatch, with the CLI auth secrets scoped to it) so the
  smoke tests get run on a schedule instead of only ad hoc by a developer.
- Preserve fail-closed token, branch, reviewer, label, and subprocess policies
  as new lifecycle capabilities are added.
- Document required token permissions in the README's "Supported toolchain"
  section so authentication setup is verified once, not diagnosed per failure.
- Add a secret-scanning hook (e.g. gitleaks or detect-secrets, not a
  hand-rolled regex) to catch hardcoded API keys, JWT tokens, or private URLs
  before they reach the source tree. A `PreToolUse` hook on `Write|Edit` is
  needed to actually prevent it (`PostToolUse` only catches it after the file
  is already written); a `gitleaks` pre-commit hook would also cover secrets
  introduced outside Claude Code's own tool calls.
- Add a `UserPromptSubmit` hook that injects fresh state before Claude reads
  the prompt: current branch, recent commits, open PR status, and whether
  `.venv/bin/python -m unittest discover -s tests` currently passes, so a run
  never starts blind on a broken build.
- Add a `PostToolUse` hook that runs Black/Ruff (and mypy) on the exact file
  Claude just touched and feeds failures back immediately, instead of only
  catching them later at `scripts/quality_gates.py --diff-base origin/main`.
- For Ralph/graph runs (not Claude Code sessions), inject into the next agent
  prompt only state the graph doesn't already track through `WorkflowState` —
  worktree drift from outside the run, or upstream `main` moving since the run
  started — as a preflight check inside `workflow/nodes.py`, not a generic
  hook, so it stays versioned and available to every downstream node.
- Map changed files to their test module by naming convention (e.g.
  `workflow/foo.py` -> `tests/test_foo.py`) and skip the run when there's no
  direct match, rather than guessing broadly at what to test.
- `./shanks doctor`'s Git/gh version check only guards a stale local dev
  machine; CI's `ubuntu-latest` always ships far newer versions, so the
  documented floor (Git 2.30, gh 2.40) is never actually exercised. Pinning
  old Git/gh versions in CI to prove the floor works is real setup effort for
  a small payoff — defer unless a real floor-version bug shows up.

Deferred

- Parallelism and additional agent roles. Revisit after isolation, recovery,
  and pull-request lifecycle behavior are reliable.
