Shanks feature roadmap

Priority 1 - Run safety and operator control

1- GitHub handoff resilience.
    Handle rate limits, network interruptions, process restarts, and idempotent
    recovery around pushes and pull-request reconciliation.

Priority 2 - Maintenance and developer experience

2- Orphan worktree and remote-branch cleanup.
    Add ownership checks, protected-branch safeguards, and a dry-run cleanup
    report for stale worktrees and branches.

3- Supported toolchain compatibility matrix.
    Document and verify supported Python, Git, and `gh` versions alongside the
    locked runtime and development dependencies.

4- Real-agent integration smoke tests.
    Exercise the Codex and Claude adapters against a small deterministic
    project so adapter drift is caught before a full workflow run.

Deferred

- Parallelism and additional agent roles. Revisit after isolation, recovery,
  and pull-request lifecycle behavior are reliable.

Suggestions

- Make GitHub handoff recovery idempotent before adding more delivery
  automation; network failures should be safe to retry without duplicate
  commits or pull requests.
- Keep cleanup ownership checks, protected-branch safeguards, and dry-run
  reporting together so stale resources are never removed by guesswork.
- Keep real-agent smoke tests opt-in or lightweight so CI remains deterministic
  while still catching changes to the Codex and Claude subprocess contracts.
- Preserve fail-closed token, branch, reviewer, label, and subprocess policies
  as new lifecycle capabilities are added.
