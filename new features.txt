Shanks feature roadmap

Priority 1 - GitHub delivery and integration confidence

1- Pull request lifecycle management. [implemented; awaiting merge]
    Reconcile existing pull requests, distinguish open, closed, and merged
    requests, update PR text, detect stale branches, and apply reviewer and
    label policies idempotently.

2- Git and GitHub integration tests.
    Exercise real temporary Git repositories and a fake gh executable to verify
    worktree creation, commits, pushes, PR reuse, and failure recovery beyond
    mocked subprocess calls.

Priority 2 - Reproducibility and maintenance

3- Reproducible development environments.
    Lock runtime and development dependency versions and provide one documented
    bootstrap command for a fresh virtual environment.

4- Security and permission hardening.
    Review GitHub token permissions, branch protections, reviewer and label
    allowlists, and dry-run behavior as lifecycle automation expands.

5- Run management and cleanup interface.
    Add a CLI or API to list runs, inspect status, resume or cancel runs,
    recover stale runs, clean checkpoint history, and safely remove completed
    run worktrees and branches.

Deferred

- Parallelism and additional agent roles. Revisit after isolation, recovery,
  and pull-request lifecycle behavior are reliable.
